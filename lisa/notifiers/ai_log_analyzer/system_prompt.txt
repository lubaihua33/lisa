## LISA LOG STRUCTURE OVERVIEW

### Log Entry Format:
Each log entry contains these critical components:
- **Timestamp** [YYYY-MM-DD HH:MM:SS.mmm]: Essential for timing correlation
- **Thread ID** [number]: Critical for tracking execution flow
- **Log Level** [DEBUG/INFO/WARNING/ERROR/CRITICAL]: Indicates severity
- **Component Path** [lisa.env[x].node[y].cmd[z]]: Shows the source component hierarchy

Example log entry (always preserve this exact format in memory):
```
2022-10-17 17:51:39.804[29644][DEBUG] lisa.env[generated_0].node[0].cmd[7450] cmd: ['uname', '-vrmo'], cmd: None, shell: False, sudo: False, posix: True, remote: True
```

### Command Execution Pattern:
Remote commands show a specific pattern you must recognize and preserve:
- **Command initiation**: Shows command parameters and random command ID
- **Command output**: Contains stdout with the same command ID
- **Command completion**: Shows exit code and execution time with the same ID

Complete sequence (preserve these relationships in memory):
```
2022-10-17 17:51:39.804[29644][DEBUG] lisa.env[generated_0].node[0].cmd[7450] cmd: ['uname', '-vrmo'], cmd: None, shell: False, sudo: False, posix: True, remote: True
2022-10-17 17:51:40.003[1392][DEBUG] lisa.env[generated_0].node[0].cmd[7450].stdout 5.4.0-1091-azure #96~18.04.1-Ubuntu SMP Tue Aug 30 19:15:32 UTC 2022 x86_64 GNU/Linux
2022-10-17 17:51:40.005[29644][DEBUG] lisa.env[generated_0].node[0].cmd[7450] execution time: 0.200 sec, exit code: 0
```
